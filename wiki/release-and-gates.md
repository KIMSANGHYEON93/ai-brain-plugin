## 이 저장소만의 제약 두 가지

`CONTRIBUTING.md`가 일반 코드 저장소와 다른 점으로 꼽는 것:

1. **`main`은 "배포 가능"이 아니라 "이미 배포 중"이다.** `/plugin marketplace add <owner>/ai-brain-plugin`은 그 순간의 `main`을 읽는다. 혼자 쓰더라도 `main`에 직접 커밋하지 않는다.
2. **절차를 여기서 고치지 않는다.** 볼트의 런북을 고치고 다시 컴파일한다.

참고로 현재 이력의 두 커밋은 모두 `main`에 직선으로 올라 있다(머지 커밋 없음). 첫 커밋은 저장소 생성이라 당연하지만, 두 번째(`d29bdbb`)도 작업 브랜치를 거친 흔적은 없다.

## 브랜치와 커밋

- GitHub Flow — `main` + 짧은 수명의 작업 브랜치(`feat/…`, `fix/…`, `chore/…`).
- 형식 `<type>(<scope>): <subject>`. **scope는 저장소 구조를 따른다:** `agents` · `skills` · `commands` · `mcp` · `hooks` · `marketplace` · `docs`.
- **컴파일 출처 푸터(필수):** `skills/`나 `agents/`를 바꾸는 커밋은 어느 런북 버전에서 나왔는지 남긴다.

  ```
  Compiled-From: RB_Notion_미러_동기화 v1.3
  ```

## pre-push 게이트 6종

`.githooks/pre-push`. `git config core.hooksPath .githooks`로 켠다 — **잊으면 검사가 아예 안 돈다.** (현재 로컬 클론에는 설정돼 있다.)

| # | 검사 | 막는 이유 |
|---|---|---|
| ① | `gitleaks git` — **커밋 이력** 전체 | 나중 커밋에서 지워도 이력에 남는다. 공개 저장소에서는 그게 유출이다 |
| ② | 플레이스홀더(`TODO-GITHUB-` + `USERNAME` 을 붙인 문자열) 잔존 | 남으면 마켓플레이스 등록이 깨진다 |
| ③ | 매니페스트 4종 JSON 유효성 | 하나만 깨져도 설치 전체 실패 |
| ④ | `.mcp.json`이 `.claude-plugin/` 안에 있지 않은지 | 위치가 틀리면 MCP 서버가 등록되지 않는다 |
| ⑤ | UUID·32자리 hex 패턴 | Notion 페이지 id·Drive 폴더 id는 시크릿이 아니라 **남의 워크스페이스 주소**다. gitleaks는 못 잡는다 (D21) |
| ⑥ | push하는 태그 = `plugin.json` 버전 | 어긋나면 릴리스와 설치본이 다른 것을 가리킨다 |

설계에서 눈여겨볼 점:

- **① gitleaks가 없으면 경고만 하고 통과한다.** 훅이 스스로 "0건이 아니라 '검사 안 함'이다"라고 출력한다. CONTRIBUTING도 "gitleaks가 0건이라고 안전이 증명되는 것은 아니다"라고 적는다 — 게이트는 마지막 방어선이지 유일한 방어선이 아니다.
- **② 플레이스홀더 문자열을 쪼개 쓴다** — 이 위키도 같은 이유로 그 문자열을 붙여 쓰지 않는다(처음엔 붙여 써서 ②에 걸렸다)(`"TODO-GITHUB""-USERNAME"`). 안 그러면 훅 파일 자체가 검사에 걸린다. ②와 ⑤는 `.githooks/`와 `CONTRIBUTING.md`를 검사 대상에서 뺀다 — 규칙을 설명하는 정당한 언급이라서.
- **⑤가 생긴 경위:** 2026-09-07 볼트의 `_plugin/` 사본에서 실제로 2건 발견됐다(`d29bdbb` 본문). 유출이 아니라 **오작동**으로 나타난다 — 설치한 사람이 원작자의 격리 페이지를 건드리게 된다.

## 알려진 함정

### ⑤는 Drive 폴더 id를 잡지 못한다

`d29bdbb` 커밋 본문과 CONTRIBUTING 표는 ⑤가 **Notion 페이지 id와 Drive 폴더 id**를 막는다고 적는다. 그런데 정규식은 소문자 hex만 본다:

```
[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}   ← 하이픈 UUID
[0-9a-f]{32}                                                   ← 붙인 32자리 hex
```

형태별로 실제로 돌려 봤다:

| 입력 형태 | 결과 |
|---|---|
| Notion id, 하이픈 UUID (소문자) | 잡힘 |
| Notion id, 32자리 hex (소문자) | 잡힘 |
| Notion id, 32자리 hex (**대문자**) | **통과** — `grep -E`에 `-i`가 없다 |
| Drive 폴더 id (33자 안팎, 영문 대소문자·숫자 섞인 base64 계열) | **통과** — hex가 아니다 |

즉 **D21의 절반(Drive 쪽)은 게이트가 아니라 사람의 주의로만 지켜지고 있다.** 09-07에 발견된 2건 중 Drive 폴더 id가 게이트로 잡힌 것이 아니라 사본 대조로 잡혔다는 뜻이기도 하다. 고치려면 Drive id 형태(길이·문자 집합)를 따로 패턴으로 추가하고 `-i`를 붙여야 하는데, base64 계열 패턴은 오탐이 많으므로 설계가 필요하다.

### ⑤는 커밋 해시에도 걸린다 — 예외 1건으로 처리함

정규식 `[0-9a-f]{32}`는 40자리 git 커밋 해시 안에도 들어 있다. 이 위키의 메타데이터 `wiki/claude-wiki.json`(`lastRunCommit`에 전체 해시를 적는다)이 그래서 push를 막았다.

**처리(09-22):** 게이트 ⑤ 결과에서 **`./wiki/claude-wiki.json`의 `"lastRunCommit": "<40자리 hex>"` 줄 하나만** 걸러낸다. 파일 통째(`--exclude=`)로 빼지 않은 이유는, 그러면 같은 파일에 Notion id가 들어와도 통과하기 때문이다. 저장소 복사본으로 확인한 동작:

| 경우 | 결과 |
|---|---|
| 현재 저장소 그대로 | 통과 |
| 같은 파일의 **다른 줄**에 Notion id | 막힘 |
| 다른 파일에 Notion id | 막힘 |
| `lastRunCommit` 값이 32자리(해시 아님) | 막힘 |
| 같은 줄을 **다른 경로**(`docs/…`)에 복사 | 막힘 |

다른 곳에서 커밋을 가리킬 때는 여전히 **7자리 짧은 해시**(`d29bdbb`)를 쓴다 — 예외는 이 한 줄뿐이다.

### ⑥은 `python3`만 쓴다

③은 `python … || python3 …`로 두 이름을 다 시도하지만, ⑥의 버전 추출은 `python3`만 부른다. Windows Git Bash에서는 `python3`이 없거나 스토어 안내 스텁일 수 있고, 그러면 버전이 `?`로 읽혀 **태그 push가 "태그 ≠ plugin.json"으로 실패한다.** (원작자 PC에서 실제로 돌려 확인하지는 않았다. 아직 태그가 한 번도 푸시된 적이 없어서 드러나지 않았을 수 있다 — 현재 태그 0개.)

### ③의 성공 메시지는 앞 단계 실패에 가려진다

`[ "$fail" = 0 ] && say "✓ 매니페스트 4종 유효"` — ①이나 ②가 이미 실패했으면 매니페스트가 멀쩡해도 ✓ 줄이 안 나온다. 결과는 맞지만(어차피 push 중단) 출력만 보면 매니페스트도 깨진 것처럼 읽힌다.

## 릴리스

플러그인 자체는 **semver**, 스킬 버전은 **원본 런북 버전**을 따른다 — 둘은 별개다.

```bash
# 1. .claude-plugin/plugin.json 의 version 을 올린다
git commit -am "chore(marketplace): v0.3.0"
git tag v0.3.0                      # 태그는 그 커밋과 같은 지점에
git push origin main --tags         # 게이트 ⑥ 이 태그·버전 일치를 확인
```

## 시크릿이 올라갔다면

커밋을 지우는 것으로 끝나지 않는다. **이미 노출된 것으로 간주하고 자격증명을 폐기·재발급**한다. 이력 재작성은 그다음이다(CONTRIBUTING §되돌리기).
